## What a project is

A project groups documents. Use one per deal, per client or per fundraise. A document can belong to several projects at once, and taking it out of a project never deletes it.

Free workspaces can have 2 projects; Pro is unlimited.

## Creating and organising

- Click the **+** next to **Projects** in the left sidebar, or **New project** on the project page.
- Give it a name and, optionally, a description. The description is shown on the project's public page.
- Add documents from the document's actions menu or from the project page.
- Documents can be in more than one project.
- Deleting a project keeps its documents, their links and their analytics. Only the project and its public page go.

## The project page for recipients

Every project has a public page that lists its shared documents, with your workspace name at the top. Recipients open documents from that list in the same viewer as a document link. Documents whose own share link is off are hidden from the list.

A **Share enabled** switch on the project page turns the public page on or off. When it is off, visitors see "This project is no longer shared".

## Project share links

Instead of sending one link per document, send the project. Every project has a default link on every plan. Giving a project more than one link, one per audience, is a Pro feature.

Each project link has:

- A private **label** and **audience** note.
- **Allow download**, which governs every document opened through that link.
- An optional **password** and **expiry**.
- An **enabled** switch: turn it off to take the whole project away from one recipient without touching the documents, their own links or anyone else's project link.

Everything a recipient opens behind a project link is attributed to that link, so you get one answer to "who came and what did they read".

## Project analytics

- The project page shows the same kind of quick stats card as a document, and each project link has its own counts: how many documents recipients opened and downloaded through it.
- Arriving at the project page is recorded even when the visitor opens nothing, so you know they came.
- In the activity feed, a document opened inside a project reads "in <project>" rather than "via <link>".
- Recipients can **Introduce yourself** from the project page header. If they do, their arrival and everything they open are labelled with the name they gave.
- On Pro, one visit through a project link that opens several documents gets a single visit brief listing the documents opened. See [Notifications and visit briefs](/help/notifications-and-visit-briefs).

Viewer identities follow the same rule as document analytics: shown on Pro, withheld on Free unless the viewer introduced themselves. See [Analytics](/help/analytics).

## Projects and your agent

An agent connected over MCP can create projects, add and remove documents, create and manage project links and read a project's documents. Deleting a project or a project link asks you to confirm first. See [Connect your agent](/help/connect-your-agent).

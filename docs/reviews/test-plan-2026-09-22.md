# Test plan

What is covered now, what is not, and what to build next — ranked by what would hurt on launch day.

Five fan-out rounds on 21–22 September found and fixed 80-odd defects, and the coverage that came
out of them is real: 2,414 unit tests, a 55-step wire-level harness driving 31 of 33 MCP tools, a
Free-plan probe, and an analytics harness. The gaps left are not in the MCP surface any more. They
are in the things no round has been able to reach from a terminal: a second human, a real browser,
a deployed server, and more than twenty documents.

Counts were correct on 2026-09-22. Search by symbol.

---

## 1. What is covered

| Harness | Scope |
|---|---|
| `tests/mcp/e2e.ts` | 55 steps. Mints a real key, drives **31 of 33 tools** in an agent's order, asserts both the MCP answer and the public URL. Now includes every share setting toggled on *and* off, with a genuinely recorded download. |
| `tests/mcp/freeplan.ts` | 20 assertions. Mints a key on a Free workspace, reaches the document cap on purpose, checks the refusal, the Pro-only gate, the clamped analytics window and that archiving clears `atLimit`. |
| `tests/mcp/analytics.ts` | `get_share_stats` and `list_share_links` against generated traffic. |
| `tests/lib/mcp*.test.ts` | 26 files: confirmations, idempotency, instruction budget, PDF optimize, source resolution, error mapping, the README and tool-description contracts (derived from source, not restated), and each round's regressions. |
| Full suite | 2,414 passing. |

Two tools are still absent from `e2e.ts` except in `EXPECTED_TOOLS`: **`archive_doc`** and
**`delete_doc`**. Both are exercised by hand in every sweep and by `freeplan.ts`, but nothing
asserts them in the harness that runs end to end.

## 2. The gaps, ranked

### A. Multi-user — the largest, and the only one that can leak data

Everything so far has run as a single owner on a single workspace. Untested:

- The role ladder. `viewer`, `member`, `admin`, `owner` are enforced by `requireOrgRole` on routes
  that name a minimum, and round four read that code without ever exercising it with two real
  users. A route that takes `member` where it means `admin` cannot be seen from one account.
- Invites end to end: create, email, claim, expire, revoke, re-invite, claim-after-revoke.
- Removal. `owner_removed` was fixed in round four on the strength of a code read. Nobody has
  actually removed a member and checked what their key does next.
- Personal versus team workspace: what a member of a team can see of the owner's personal one.

**How to test it.** A harness like `freeplan.ts` that mints two accounts and two keys, walks the
ladder, and asserts that each refusal is a refusal rather than a silent success. Every write route
that accepts an org, doc, project or link id should be called with an id from the *other*
workspace, and answer `not_found` or `forbidden`.

**Why it is first.** Every other gap on this list produces a wrong number or an ugly page. This one
can produce someone else's document.

### B. The browser — the only surface nothing has looked at

Every assertion so far has been an HTTP status or a JSON field. The sidebar bug the owner caught by
eye on 2026-09-21 is the shape of what this misses: the server was correct, `list_starred` returned
zero, and the page still showed a deleted document because nothing had told it. Realtime frames,
hydration, the metrics charts, the tags manager under a real click — none of it is asserted.

**How to test it.** Playwright against `npm run dev`, with the seeded workspace: open a document
page, drive an MCP write from the test, assert the page updates without a reload. That single
assertion covers the class the screenshot found.

### C. Scale — every list in the product is small right now

Twenty documents, 37 links, 19 tags, 7 readers. The paging, the caps and the truncation warnings
are all written for more than that and have never met it. Known specifics already in the code:
`list_share_links` truncates at 100 and says so; the tag page caps items at 200 (fixed in round
four, never driven); `GET /api/docs` caps `ids` at 50 and `list_docs` chunks around it.

**How to test it.** Seed a throwaway workspace with 500 documents, 2,000 links and 300 tags —
`seed.py` already does the shape, only the numbers change — then page every listing to the end and
assert no row is dropped or repeated.

### D. The deployed server — nothing has run anywhere but localhost

`mcp.lnkdrp.com` is unshipped. OAuth is scoped in `docs/prds/lnkdrp-mcp-oauth.md` and not built, so
`authorization_servers` is empty and a cloud connector cannot authenticate at all. Sessions are
in-memory and the Fly app is pinned to one machine, so every deploy drops connected agents and the
24h idempotency cache goes with it — a retry after a restart creates a duplicate rather than
replaying. None of that is a bug; all of it is untested behaviour on the only environment that will
matter.

### E. The two harness holes

`archive_doc` and `delete_doc` in `e2e.ts`, and the two open items from the September 21 audit that
are still open: a guard for the dropped-field class (five separate incidents of the API client
whitelisting away a field a route had added), and shape parity between the two branches of the
tools that have two.

---

## 3. Order

1. **Multi-user harness** (A). Two accounts, the role ladder, cross-workspace ids.
2. **One Playwright assertion** (B): an MCP write reaching an open page. Widen later.
3. **`archive_doc` and `delete_doc` in `e2e.ts`** (E). Cheap, and closes the last tool gap.
4. **Dropped-field guard** (E). Five incidents of one mechanism earns a mechanism-level test.
5. **Scale seed** (C). Worth doing before the first customer with a real library.
6. **Deploy and OAuth** (D). Blocked on product decisions, not on testing.

Items 1 to 4 are a day's work between them. Item 5 is an afternoon. Item 6 is a project.

---

## 4. What this plan deliberately does not include

Another broad MCP sweep. Five rounds found 80-odd defects, but the fifth found mostly documentation
drift and two tests that guarded nothing, and its most valuable output was a checker catching an
agent misreporting its own work. The surface is swept. The next defect there will come from a
change, not from another look at the same code — so the trigger for round six should be a diff,
not a schedule.
